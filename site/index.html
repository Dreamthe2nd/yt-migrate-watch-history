Python 3 · Playwright · sqlite3 — one file, zero framework

Replay your entire YouTube watch history — one video at a time.

migrate_watch_history.py replays every video in scraped_history.json in reverse order, dwells a randomized 20–45 seconds on each page, and commits every completion to a local SQLite database. Interrupt it at any moment — it always resumes exactly where it left off.

01 · Pipeline

How it works

Five steps, executed once per URL, in strict order.

  1. 1

    Load & reverse

    Reads scraped_history.json (a JSON array of full video URLs), trims whitespace, and reverses the array so videos are processed from the original last index down to the first — index -1 → 0.

  2. 2

    Skip what's already done

    Every URL is checked against state.db before visiting. URLs already recorded are skipped instantly — this is what makes every re-run idempotent and what powers safe resumption.

  3. 3

    Watch the page

    Navigates with wait_until="domcontentloaded" (60 s timeout), waits up to 5 s for the <video> element, injects a small JS snippet that starts playback if the player is paused, then dwells on the page for a randomized 20–45 seconds.

  4. 4

    Commit immediately

    The instant the dwell completes — success or failure — the URL is inserted into watched_videos and conn.commit() runs before the next URL starts. A crash can never lose more than one in-flight view.

  5. 5

    Resume on re-run

    Ctrl+C, crash, or power loss — just run the script again. It counts what's in state.db, skips it, and continues. Failed URLs stay marked (attempted); delete their row to retry them.

Key reliability decisions

  • domcontentloaded, never networkidleYouTube streaming and telemetry sockets stay open indefinitely — networkidle would hang and time out on essentially every video.
  • --mute-audio at browser launchViews register without sound or notifications; a muted player is also what browsers allow to autoplay.
  • launch_persistent_context(./chrome_profile)The login lives in a persistent local profile, so the manual login happens exactly once — ever.
  • Per-URL try/exceptOne removed video, region block, or transient network error logs a warning and marks the URL as attempted instead of killing a multi-day run.
  • Random 20–45 s dwellLong enough for YouTube to treat each video as genuinely watched, randomized so the rhythm doesn't look mechanical.

02 · Install

Prerequisites & installation

Python 3.10+ and Playwright. That's the entire dependency tree.

Requirements

  • Python 3.10 or newer — 3.11 / 3.12 recommended
  • pip — ships with Python on most installs
  • A desktop session — first run needs a visible browser window for the manual YouTube login
  • Steady internet + a machine you can leave on — the full 18,453-video migration runs for several days

Linux only: Chromium also needs a few system libraries (installed in the next step with install-deps).

Install

terminal
python3 --version        # 3.10 or newer

python3 -m venv .venv
source .venv/bin/activate    # Windows: .venv\Scripts\activate

pip install playwright
playwright install chromium
# Linux only, once — installs system libraries (needs sudo):
# playwright install-deps chromium

# verify
pip show playwright
python -c "from playwright.sync_api import sync_playwright; print('playwright OK')"

03 · Setup

Setup

Three things: your data file, the first run, and the artifacts it creates.

Step 1 — Place scraped_history.json next to the script

The input is a plain JSON array of full video URLs, one item per video. Paths are resolved relative to the script, so the file must sit in the same directory as migrate_watch_history.py. The reference migration contains 18,453 entries. Duplicates are harmless — the primary key keeps them in the state store exactly once.

scraped_history.json
[
  "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
  "https://www.youtube.com/watch?v=9bZkp7q19f0",
  "https://www.youtube.com/watch?v=hY7m5jjJ9mM"
  /* …18,450 more… */
]

See scraped_history.example.json in the repo for a ready-made shape reference. The real data file is gitignored — it's yours and stays local.

Step 2 — First run & manual login

Because state.db starts empty (0 completed videos), the script pauses and prompts you in the terminal to log in manually in the browser window it opens:

terminal — first run
$ python migrate_watch_history.py
Loaded 18453 URLs from scraped_history.json; processing in reverse order (index -1 -> 0).
Dwell per video: 20-45s (random). State: state.db

state.db is empty (0 completed videos).
Log in to your YouTube account in the browser window,
then press ENTER here to start the migration...
↵

The login is stored in chrome_profile/ — every later run picks the session up automatically and skips the prompt.

04 · Run

How to use

One command. One line of telemetry per video. Safe to stop, safe to restart.

terminal
$ python migrate_watch_history.py
Loaded 18453 URLs from scraped_history.json; processing in reverse order (index -1 -> 0).
Dwell per video: 20-45s (random). State: state.db
Resuming run: 1204 URLs already recorded in state.db.

[1205/18453] | Watched 31s  | Remaining: 17248 | ETA: ~155.1 hours
[1206/18453] | Skipped (already in state.db) | Remaining: 17247 | ETA: ~155.1 hours
[1207/18453] | Watched 24s  | Remaining: 17246 | ETA: ~154.9 hours
[1208/18453] | WARNING: view failed (TimeoutError: page.goto: Timeout 60000ms exceeded) - marked as attempted | Remaining: 17245 | ETA: ~154.9 hours
[1209/18453] | Watched 41s  | Remaining: 17244 | ETA: ~154.7 hours
…

Telemetry format: [Current/Total] | Watched Xs | Remaining: Y | ETA: ~Z hours. The ETA is computed from the observed average per-watch time (dwell + navigation overhead), falling back to the 32.5 s dwell midpoint until the first view completes.

Interrupt & resume

Press Ctrl+C at any time. Every finished view is already committed, so:

later
python migrate_watch_history.py
# -> "Resuming run: N URLs already recorded"

Retry a failed URL

Failed URLs are marked as attempted (committed) on purpose — one dead link must never stall a multi-day run. To replay one, delete its row and re-run:

terminal
sqlite3 state.db "DELETE FROM watched_videos
WHERE url = 'https://www.youtube.com/watch?v=...';"

Re-run after completion

When the list is exhausted, every URL hits the skip path, so a re-run finishes in seconds and confirms the final count:

terminal
Done. 18453/18453 URLs recorded in state.db.

05 · Reference

Runtime, schema & design

The numbers, the state store, and the architecture rules the script follows.

Runtime estimate — 18,453 videos

ScenarioDwellWall time (dwell only)With overhead
Fastest20 s every video≈ 102.5 h (4.3 days)≈ 5 days
Typical32.5 s average≈ 166.6 h (7.0 days)≈ 8–9 days
Slowest45 s every video≈ 230.7 h (9.6 days)≈ 11 days

Overhead = navigation (~1–3 s) + up to 5 s player wait per video. Skips cost ~0 s. Plan to leave the machine on for roughly a week, powered and with the screen unlocked or a screensaver that doesn't kill the browser.

State schema

state.db — sqlite3
CREATE TABLE IF NOT EXISTS watched_videos (
  url        TEXT PRIMARY KEY,
  watched_at TIMESTAMP
);
-- per video, committed immediately after the dwell:
INSERT OR IGNORE INTO watched_videos (url, watched_at)
VALUES (?, '2026-09-24T07:41:05+00:00');

Idempotency comes from the primary key + INSERT OR IGNORE, plus the pre-visit lookup that skips recorded URLs before the browser even opens a tab.

Playback nudge

injected once per video
() => {
  const v = document.querySelector("video");
  if (v && v.paused) {
    v.muted = true;
    v.play().catch(() => {});
  }
}

Runs right after the player element appears. If the page is mid-navigation when it fires, the failure is swallowed — the dwell still counts.

Architecture rules

⛔ What it is not

  • No classes, no frameworks, no ORM
  • No external dependency beyond playwright — the rest is stdlib (json, sqlite3, random, time, pathlib)
  • No abstractions — one main(), two tiny helpers

✅ What it is

  • One ~180-line file, readable top to bottom in two minutes
  • Idempotent by construction: every re-run is a resume
  • Failure-isolated: the loop can never die on a single URL
  • State is a plain SQLite file you can inspect with any tool

FAQ

Why is the array reversed?

The script processes the list from its last entry to its first (original index -1 → 0), as specified for this migration — so if your scrape was newest-first, playback effectively runs in chronological order.

Why domcontentloaded and not networkidle?

YouTube keeps streaming, telemetry, and social sockets open for as long as the page exists. networkidle requires a quiet window that effectively never arrives, so navigation would time out on most videos. domcontentloaded returns as soon as the page is usable, and the short <video> wait handles the rest.

Why is the browser window visible, and why is audio muted?

Visible (headless=False) because the one-time login is manual — and because consent, age, or re-auth walls that YouTube may surface mid-run are best clicked through by a human. Audio is muted with the --mute-audio launch flag so the machine stays silent for days and muted autoplay is always permitted.

What exactly happens to a failed URL?

The warning is logged, then the URL is inserted into watched_videos like any other — "marked as attempted" — and the loop moves on. That trade-off keeps a single 404 from stalling an 8-day run. Delete the row (see Usage) if you want a specific URL replayed.

Can I run it headless?

The script is deliberately pinned to a visible window so login and occasional walls are human-handled. If you've completed a login and trust the session, changing headless=False to headless=True in the launch call is a one-character edit — do it with a warm profile.

Is the data safe / private?

Everything stays local: the JSON input, the SQLite state, and the browser profile never leave your machine. The only network traffic is Playwright driving your own logged-in YouTube session to the URLs in your file.
